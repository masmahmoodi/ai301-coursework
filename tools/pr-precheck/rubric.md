# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | The diff's changed file list read side-by-side against the plan's stated scope (files named, boundary statement) and deviation notes; and the PR description's fidelity claims read against the diff's actual contents. | Pass when every file in the diff falls inside the plan's stated boundary OR a deviation note explicitly names and explains the extra change; AND the description does not claim changes the diff does not contain, nor omit changes the diff does contain. Fail when any file appears in the diff that the plan never named and no deviation note accounts for, OR when the description's stated scope contradicts what the diff shows. | required |
| test-evidence | The test-evidence section (or test_evidence.md in live mode) read against the plan's test plan: specifically, whether a before-state names an observable failure, an after-state shows the fix in effect, and the repo's required checks (make test-unit, make test-integration, make lint, make typecheck) have visible pass/fail outcomes. | Pass when the evidence includes: (a) a before-state artifact showing the failure the plan aimed to fix (error output, failing assertion, or wrong behavior), (b) an after-state artifact showing the corrected behavior on the same code path, and (c) visible outcomes for the repo's own required checks. Evidence must exercise the actual code path changed, not an unrelated path. A PR that honestly discloses that end-to-end evidence was impossible (with an explained substitute that covers the code path) passes this check. Fail when evidence is missing entirely, says only "tests pass" without output, or exercises a different code path than the change. | required |
| diff-quality | The unified diff and commit list read for debris: debug statements, commented-out blocks, dead code, unrelated hunks, and formatting churn that buries the fix. | Pass when the fix named in the plan is visible in the diff AND every hunk in every file serves the plan's stated fix (or a deviation note accounts for it). Fail when the diff contains debug statements not required by the fix, commented-out code blocks, large formatting-only hunks that bury the actual change, or edits to files unrelated to the plan's scope that no deviation note explains. | required |
| standards-comms | The PR template sections (Summary, Issue, Changes, Testing, Notes for Reviewers) read for real content vs. placeholder; the repo's AI-use disclosure requirement (from CONTRIBUTING.md or repo-facts block) read against the Notes for Reviewers section; and any explicit maintainer direction in the issue thread read against the PR description. | Pass when every template section contains real content (not just the HTML comment placeholder), the AI disclosure statement appears where the repo requires it, and no explicit maintainer direction in the thread (named file, suggested approach, posted patch) is ignored without explanation. A disclosed shortfall in Notes for Reviewers is real content. Fail when any section contains only placeholder text, when AI disclosure is absent and the repo requires it, or when the PR ignores explicit maintainer direction. | required |

## Verdict rule

Accept if every required check passes. Reject if any required check fails.

Unclear counts as fail: an `unclear` grade on any required check produces a `reject` verdict. A fact or claim the package does not allow verification of is a claim that is not ready to submit.

Preferred checks never appear in this rubric; all checks are required. A PR that honestly discloses a shortfall and substitutes verifiable evidence for the thing it could not do still passes the affected check — the honest-outcome rule means "less than everything" does not automatically mean "hold", provided the substitute evidence covers the code path.
